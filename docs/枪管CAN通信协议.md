# 电管外设 CAN 通信协议

包含枪管协议 v3.5（`SHOOT_cmzy_REV081`）与装甲板协议 v1.3（`Armor_Cmzy26_081`）。

经典 CAN、标准 11 位 ID、数据帧（`CAN_RTR_DATA`）、500 kbps；多字节整数均为小端序。装甲板使用 `0x1xx`，枪管使用 `0x2xx`。

## 当前生效：装甲板自动 NodeID

四块装甲板使用同一 bin。电管按完整 STM32 UID 的字典序固定分配 NodeID 1~4；未分配节点不发送或处理业务帧。正式固件要求 4 块全部到齐；测试固件可通过 `APP_ARMOR_ENUM_REQUIRED_NODE_COUNT` 编译宏设为 `1~3`，用于部分装甲板联调。

| ID | 报文 | DLC | 关键字段 |
|---:|---|---:|---|
| `0x120` | `ENUM_START` | 1 | Byte0=`session` |
| `0x121` | `ENUM_ANNOUNCE` | 8 | `session`、UID 分片 0~3、UID hash 低 24 bit |
| `0x122` | `NODE_ASSIGN` | 8 | `session`、NodeID、token、UID CRC16-CCITT |
| `0x123` | `NODE_ACK` | 8 | 分配字段回显，Byte7=`0xA5` |

`ENUM_ANNOUNCE` 的 Byte0=`session`、Byte1=`fragment`、Byte2~4=UID 三字节、Byte5~7=token。装甲板收到枚举后延迟 `5 + hash % 50` ms 上报，失败时退避重发；电管收齐 4 个完整 UID 后逐板分配并等待 ACK。缺板、多板、校验失败或 ACK 超时将重新枚举。

业务 ID：`0x130 + (NodeID - 1) × 0x10 + offset`。offset 为 `0=reset`、`1=fault`、`2=init`、`3=hit`、`4=status query`、`5=status reply`、`6=LED control`、`7=LED ACK`、`8=NodeID query`、`9=NodeID reply`、`10=hit ACK`；Node 1 为 `0x130~0x13A`，Node 4 为 `0x160~0x16A`。电管在全部 ACK 后每 25 ms 查询下一个节点，因此每块板查询频率为 10 Hz。

## 1. 报文速查

### 1.1 ID 范围

| 外设 | 调试层 | 故障层 | 设备层 | 应用层 |
|---|---|---|---|---|
| 装甲板 | `0x100~0x10F` | `0x110~0x11F` | `0x120~0x12F` | `0x130~0x13F` |
| 枪管 | `0x200~0x20F` | `0x210~0x21F` | `0x220~0x22F` | `0x230~0x23F` |

### 1.2 枪管报文

| ID | 方向 | 报文 | DLC | 行为 |
|---:|---|---|---:|---|
| `0x200` | 枪管→电管 | 调试心跳 | 8 | 预留，当前不发送 |
| `0x210` | 枪管→电管 | 强故障复位原因 | 1 | 异常复位后的初始化完成时发送 |
| `0x211` | 枪管→电管 | 弱故障状态 | 1 | 故障发生、持续或清除时发送 |
| `0x212` | 枪管→电管 | 初始化完成 | 0 | 初始化后发送一次 |
| `0x220` | 电管→枪管 | 传感器校正请求 | 0 | 收到后在主循环执行 |
| `0x221` | 枪管→电管 | 传感器校正 ACK | 8 | 校正完成或失败后发送 |
| `0x230` | 枪管→电管 | 有效射击事件 | 8 | 每次有效射击发送 |
| `0x231` | 电管→枪管 | 射击状态查询 | 0 或 8 | 收到后回复 `0x232` |
| `0x232` | 枪管→电管 | 射击状态回复 | 8 | 回复 `0x231` |
| `0x233` | 电管→枪管 | LED/队伍/热量控制 | 8 | 有效命令执行 |
| `0x234` | 枪管→电管 | 控制 ACK | 8 | 原样回显 `0x233` 数据 |

### 1.3 枪管 `0x233` 命令

| Byte0 | 功能 | Byte1 |
|---:|---|---:|
| `0x00` | 恢复自动模式 | 无 |
| `0x01` | 设置红队 | 无 |
| `0x02` | 设置蓝队 | 无 |
| `0x03` | 设置当前热量 | `0~200` |
| `0x10` | 全绿测试 | 无 |
| `0x11` | 全红测试 | 无 |
| `0x12` | 全蓝测试 | 无 |
| `0x1F` | 全灭 | 无 |

### 1.4 装甲板报文

| ID | 方向 | 报文 | DLC | 行为 |
|---:|---|---|---:|---|
| `0x110` | 装甲板→电管 | 异常复位原因 | 1 | 异常复位后的初始化完成时发送 |
| `0x111` | 装甲板→电管 | 运行故障状态 | 2 | 变化立即发送；非零时每 100 ms 重发 |
| `0x112` | 装甲板→电管 | 初始化完成 | 0 | 初始化后发送一次 |
| `0x130` | 装甲板→电管 | 有效击打事件 | 8 | 每次有效 HIT 入队发送 |
| `0x131` | 电管→装甲板 | 状态查询 | 0 或 8 | 收到后回复 `0x132` |
| `0x132` | 装甲板→电管 | 状态回复 | 8 | 回复 `0x131` |
| `0x133` | 电管→装甲板 | LED 控制 | 8 | 合法命令执行后回复 `0x134` |
| `0x134` | 装甲板→电管 | LED 控制 ACK | 8 | 原样回显 `0x133` 数据 |
| `0x13A` | 电管→装甲板 | 有效击打 ACK | 1 | Byte0=待确认的 HIT sequence |

### 1.5 装甲板 `0x130` 有效击打事件

| 字节 | 字段 | 编码 |
|---|---|---|
| Byte0 | `sequence` | 本板递增；重传保持不变 |
| Byte1 | `channel` | 当前恒为 `0xFF`，表示四通道融合判定 |
| Byte2 | `intensity` | `0~100`，未完成力度标定时为 0 |
| Byte3~4 | `force_01n` | `uint16_t` 小端，单位 0.01 N；未标定时为 0 |
| Byte5~7 | `sum_peak` | `uint24_t` 小端，保留原峰值低 24 bit |

L431 对新 sequence 扣一次血并通过同一 NodeID 的 `offset=10`、`DLC=1` 回 ACK。重复 sequence 只重发 ACK、不重复扣血；装甲板未收到 ACK 时每 100 ms 重发。

### 1.6 装甲板 `0x132` 状态回复

| 字节 | 字段 | 编码 |
|---|---|---|
| Byte0 | `state` | 0=BOOT，1=NORMAL，2=HIT，3=FAULT，4=COMM_LOST，5=ID_SETUP，6=ID_CONFLICT |
| Byte1 | `reset_cause` | 与 `0x110` Byte0 相同；正常启动为 0 |
| Byte2~3 | `hit_fault_flags` | `uint16_t` 小端 |
| Byte4~5 | `temp_fault_flags` | `uint16_t` 小端；未实现时为 0 |
| Byte6 | `can_health` | bit0=错误警告，bit1=错误被动，bit2=Bus-Off |
| Byte7 | 保留 | 固定为 0 |

### 1.7 装甲板 `0x133` 命令

| Byte0 | Byte1 | 行为 |
|---:|---:|---|
| `0x00` | 忽略 | 切换为 `LED_EFF_NORMAL` |
| `0x01` | 忽略 | 设置红队 |
| `0x02` | 忽略 | 设置蓝队 |
| `0x03` | `0~100` | 设置 LED 亮度百分比 |
| `0x04` | `0~6` | 设置现有 `led_effect_t` 灯效值 |

## 2. 枪管协议说明

### 故障与启动

`0x210` 的 Byte0：bit0=HardFault，bit1=看门狗复位，bit2=CAN Bus-Off，bit3=其他异常复位，bit7=未定义强故障。强故障发生时先保存标志并复位；初始化成功后按 `0x210 → 0x212` 顺序发送。

`0x211` 的 Byte0：bit0=前端传感器，bit1=后端传感器，bit2=发射检测/测速，bit3=关键任务，bit4=事件队列，bit7=未定义弱故障。同类异常连续确认 3 次后置位；故障持续时约每 100 ms 重发，恢复时发送 0。

`0x212` 为 DLC=0 的初始化完成帧。正常启动只发送 `0x212`。

### 传感器校正

`0x220` 只接受标准数据帧、DLC=0。枪管读取前、后 VCNL4040 各 20 次 `PS_DATA` 取平均作为 baseline，设置 `THDL=baseline-20`（下限为 0）、`THDH=baseline`，中断模式为 AWAY。过程在主循环执行。

`0x221` 为四个 `uint16_t` 小端字段：前端校正前/后 baseline、后端校正前/后 baseline。校正失败时对应“校正后 baseline”为 `0xFFFF`。

### 射击状态与热量

`0x230`：Byte0~3 为累计有效射击次数，Byte4~5 为本次速度（0.01 m/s），Byte6 为 `barrel_mask` 低 5 位，Byte7 为本次射击后的热量（0~200）。后端先触发、前端后触发，且速度在 0~50 m/s 时确认有效射击。

`0x231` 接受 DLC=0，或 DLC=8 且全部为 0。电管当前每 100 ms 发送一次 `0x231`，并与装甲板 25 ms 轮询错开。枪管在主循环发送 `0x232`，不在 CAN 接收中断内抢占邮箱。`0x232` 的 Byte0~3 为累计次数，Byte4~5 为最近速度（0.01 m/s），Byte6 为 `barrel_mask`，Byte7 为当前热量。

上电/复位后热量为 0；每次有效射击加 10，最大钳位为 200；每满 1 秒自动减 10，最低为 0。比赛开始时，电管会通过 `0x233` 命令 `0x03` 请求枪管清零热量，并持续重试直到收到匹配的 `0x234` ACK。

### 枪管 LED 控制

`0x233` 必须为 DLC=8，Byte2~7 填 0。未知命令、热量越界或格式错误时忽略且不 ACK。有效命令后以 `0x234` 原样回显全部 8 字节。

### 非 CAN 调试接口

枪管 USART2 的 `F`、`R`、`D` 用于前端 5 秒、后端 5 秒、双通道 200 Hz/10 秒采集，不属于 CAN 协议。

## 3. 装甲板协议说明

### 故障与启动

`0x100~0x10F` 为预留范围。协议不含链路心跳和通信超时判定。

`0x110` 的 Byte0：bit0=HardFault，bit1=独立/窗口看门狗复位，bit2=CAN Bus-Off 触发的受控复位，bit3=MemManage、BusFault、UsageFault、选项字节或低功耗等其他异常复位。异常复位后按 `0x110 → 0x112` 顺序发送；普通上电、NRST 和常规软件复位不发送 `0x110`。

`0x111` 为 `uint16_t` 小端原始故障位图，清除时发送 `0x0000`。 `0x112` 为 DLC=0 初始化完成帧。

### 击打与状态

`0x130` 事件先进入四项 FIFO，CAN 邮箱暂忙时后续主循环重试；队列满时丢弃最新事件。

`0x131` 接受 DLC=0，或 DLC=8 且 Byte0~7 全为 0。电管每 100 ms 发送一次 `0x131`；`0x132` 的字段见速查表。

### 装甲板 LED 控制

`0x133` 必须为 DLC=8，Byte2~7 必须为 0。未知命令、参数越界、保留字节非零，或装甲板处于 `FAULT`/`COMM_LOST` 时静默忽略且不回复 ACK。有效命令后 `0x134` 原样回显全部 8 字节。

### 预留与联调

`0x120~0x12F` 当前不被接受。CAN 参数读写、零偏标定和 Flash 双槽 CRC 掉电保存尚未实现。

普通上电应观察一次 `0x112`；异常复位后应先收到 `0x110` 再收到 `0x112`。击打时核对 `0x130` 的 `sum_peak` 与串口 HIT 日志；分别使用 DLC=0 和 DLC=8 全 0 查询 `0x131`，确认收到 `0x132`。
