# L431 与四个装甲板节点 CAN 通信测试计划书

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 适用工程 | `L431PM` 与 `new_armor/Armor_Cmzy26_081` |
| 被测主控 | STM32L431RC，CAN1，500 kbps |
| 被测节点 | 4 个 STM32L432 装甲板，烧录同一版本固件 |
| 测试对象 | 物理链路、CAN 驱动、接收队列、枚举、业务轮询、故障和恢复 |
| 计划版本 | v1.0 |
| 记录时间基准 | CAN 分析仪硬件时间戳；L431 调试计数器；装甲板串口日志 |

## 2. 测试目标

确认以下行为满足协议和工程要求：

1. L431 能稳定发现四个装甲板，并按 UID 稳定分配 NodeID `1~4`。
2. 枚举完成后，四个节点均能持续完成状态查询和状态回复。
3. 单个节点掉线、复位、重新接入时，不影响其他节点的业务通信。
4. 枚举不会无故周期性重复；一次枚举过程不会自行制造“节点离线”。
5. CAN 驱动在仲裁延迟、无 ACK、错误帧、Bus-Off、邮箱占满和接收突发情况下可恢复。
6. 命中事件、ACK、故障状态、LED 控制及身份查询的数据和时序正确。
7. CAN 通信负载不会饿死 L431 的 ADC、电源保护、看门狗和串口任务。
8. 长时间运行、断电重启、节点热插拔和多种故障组合下系统行为可解释、可诊断。

## 3. 被测架构和协议基线

```text
装甲板 1 ─┐
装甲板 2 ─┼── CAN1 500 kbps ── L431PM
装甲板 3 ─┤
装甲板 4 ─┘
```

CAN 使用标准 11 位数据帧、经典 CAN、500 kbps。装甲板业务 ID 由 NodeID 决定：

```text
业务基址 = 0x130 + (NodeID - 1) * 0x10
```

| ID | 方向 | DLC | 说明 |
|---:|---|---:|---|
| `0x120` | L431 -> 装甲板 | 1 | 枚举启动，Byte0=session |
| `0x121` | 装甲板 -> L431 | 8 | UID 分片，共 4 片/节点 |
| `0x122` | L431 -> 装甲板 | 8 | NodeID 分配 |
| `0x123` | 装甲板 -> L431 | 8 | 分配 ACK，Byte7=`0xA5` |
| `0x134/144/154/164` | L431 -> 装甲板 | 0 | Node 1~4 状态查询 |
| `0x135/145/155/165` | 装甲板 -> L431 | 8 | Node 1~4 状态回复 |
| `0x136/146/156/166` | L431 -> 装甲板 | 8 | LED 控制 |
| `0x137/147/157/167` | 装甲板 -> L431 | 8 | LED 控制 ACK |
| `0x130/140/150/160` | 装甲板 -> L431 | 8 | 命中事件 |
| `0x13A/14A/15A/16A` | L431 -> 装甲板 | 1 | 命中事件 ACK |
| `0x138/148/158/168` | L431 -> 装甲板 | 0 | 身份查询 |
| `0x139/149/159/169` | 装甲板 -> L431 | 8 | 身份回复 |

正式版本需要四个节点。枚举成功后 L431 每 25 ms 查询一个节点，因此每个节点目标频率为 10 Hz，状态回复通常应保持约 100 ms 间隔。

## 4. 测试环境和仪器

- L431PM 实物板和稳定可调电源。

- 示波器，至少观察 CANH、CANL、差分信号、复位和电源电压。

- 4 路独立电源开关或继电器，用于节点热插拔和掉电测试。
- 120 ohm 可切换终端电阻、短接线、可控 CAN 故障注入设备。
- L431 的 LPUART1 调试串口、4 个装甲板日志串口。

## 5. 通用通过标准

- 所有合法帧：ID、方向、DLC、数据字段和顺序符合协议。
- 枚举成功后 NodeID 固定为 `1~4`，同一 UID 在重复上电后获得相同 NodeID。
- 正常运行 10 分钟内不出现非人为触发的 `0x120`。
- 每个节点状态回复间隔目标为 `100 ms`，正常最大间隔不超过 `300 ms`。
- 无误码、无异常 Bus-Off、无接收队列溢出、无发送邮箱永久占用。
- 任意一个节点断开后，其他在线节点仍能继续回复。
- 节点恢复后能在规定时间内重新枚举并恢复业务。
- L431 看门狗不复位，ADC 有效采样率和电源保护功能无明显异常。
- 测试结束时诊断计数器、CAN 分析仪统计和串口日志能够相互对应。

## 6. 测试项目

### 6.1 物理层和基础配置

| 编号 | 测试 | 方法 | 通过标准 |
|---|---|---|---|
| PHY-01 | CANH/CANL 静态电平 | 上电、空闲和通信时示波器测量 | 空闲为隐性，显性差分方向正确，无明显振铃 |
| PHY-02 | 终端电阻 | 断电测 CANH-CANL 电阻 | 两端各 120 ohm 时总阻值约 60 ohm；不得重复并联过多 |
| PHY-03 | 波特率 | 分析仪测 bit time 和采样点 | 500 kbps，采样点与 CubeMX/固件配置一致 |
| PHY-04 | 长线和负载 | 逐步增加线长及节点数量 | 无错误帧和通信失步，记录最大稳定距离 |
| PHY-05 | 电源扰动 | 节点电源缓慢升降、瞬时跌落 | 不产生持续错误风暴；复位后能重新入网 |
| PHY-06 | 接插件和地线 | 轻微振动、插拔、检查共地 | 不出现随机周期枚举；故障可由错误计数解释 |

### 6.2 上电和枚举

| 编号 | 测试 | 方法 | 通过标准 |
|---|---|---|---|
| ENUM-01 | 四板冷启动 | 四板同时上电，记录完整 30 s | 仅有必要枚举；四板各发送 4 个 `0x121` 分片 |
| ENUM-02 | UID 完整性 | 核对 12 字节 UID、FNV token、CRC16 | L431 计算值与装甲板日志一致 |
| ENUM-03 | NodeID 排序 | 记录 UID 与 NodeID 对应关系 | 按 UID 字典序稳定分配 `1~4` |
| ENUM-04 | ACK 顺序 | 检查 `0x122/0x123` | 每次只分配一个节点，ACK 校验通过后才进入下一个 |
| ENUM-05 | 重复上电 | 重启 L431、单板、四板组合各 10 次 | 无 NodeID 漂移、无卡死、无无限枚举 |
| ENUM-06 | 单板缺失 | 分别只连接 3、2、1 个节点 | 正式宏设为 4 时不进入业务；测试宏行为符合配置 |
| ENUM-07 | 枚举帧丢失 | 屏蔽或注入丢失 `0x121` 分片 | 在超时后重试，最终恢复；不错误接受不完整 UID |
| ENUM-08 | ACK 丢失 | 丢弃指定 `0x123` | 只重试当前分配，不接受错误节点 ACK |
| ENUM-09 | 错误 token/CRC | 修改 `0x121` 或 `0x123` 字段 | 拒绝该节点或该 ACK，记录 invalid/timeout |
| ENUM-10 | session 过期 | 延迟旧 session 的帧 | 旧帧不得污染当前枚举表 |
| ENUM-11 | 同 ID 竞争 | 让四板同步发送 announce | 允许重试恢复；不可出现错误 UID、错误 NodeID 或死循环 |
| ENUM-12 | 人工启动枚举 | 注入合法 `0x120` | 四板清除 NodeID、重新分配后恢复业务 |
| ENUM-13 | 已完成枚举后观察 | 连续运行 10 分钟 | 无人为触发时不应再次出现 `0x120` |

### 6.3 正常业务轮询

- 验证 `0x134/0x144/0x154/0x164` 按 NodeID 轮流发送。
- 统计每个节点的查询数、回复数、回复率和最大间隔。
- 发送 DLC=0 和兼容格式 DLC=8 全 0 的查询，均应得到合法 `0x135/145/155/165` 回复。
- 发送错误 DLC、错误保留字节和错误 ID，装甲板应静默忽略。
- 连续运行 1 分钟、10 分钟和 1 小时，检查查询节拍是否漂移。
- 观察枚举期间已有节点状态是否仍可更新，且不会被在线超时误判。

判定要求：每节点正常状态回复率至少 99.5%；人为断开除外，最大间隔不得超过 300 ms；不允许因一次延迟回复触发重枚举。

### 6.4 状态和故障字段

逐一让装甲板进入或模拟以下状态：`BOOT`、`NORMAL`、`HIT`、`FAULT`、`COMM_LOST`、`ID_SETUP`、`ID_CONFLICT`。

检查：

- Byte0 状态值与装甲板内部状态一致。
- Byte1 复位原因与实际复位原因一致。
- Byte2~3 命中故障位小端解析正确。
- Byte4~5 温度故障位小端解析正确。
- Byte6 CAN 健康位与错误状态一致。
- `state=FAULT` 不被误当作通信离线；只按收到报文判断在线。
- Node 3/4 的 `state=3`、`fault_flags=0x1000` 必须查明具体故障位定义并单独记录。

### 6.5 命中事件和可靠性

| 编号 | 测试 | 通过标准 |
|---|---|---|
| HIT-01 | 单次命中 | L431 收到一次新 sequence，只计一次 |
| HIT-02 | 重复 HIT | 重复帧可重发 ACK，但不得重复扣血 |
| HIT-03 | ACK 丢失 | 装甲板按约 100 ms 重传相同 sequence |
| HIT-04 | 错误 ACK | 不移除错误 FIFO 项，不影响后续事件 |
| HIT-05 | 四节点同时命中 | 四个 NodeID 事件分别归属正确，无串号 |
| HIT-06 | FIFO 满 | 记录溢出策略，系统不死锁、不误扣血 |
| HIT-07 | 重枚举后重复事件 | 同 UID 的去重状态符合设计；新节点或复位状态正确清除 |

### 6.6 LED 控制和身份查询

- 对四个节点分别发送红队、蓝队、亮度和灯效命令。
- 检查合法命令的 ACK 是否原样回显。
- 检查参数越界、保留字节非零、未知命令和故障状态下是否静默忽略。
- 执行 `ARMOR=LIST`，核对 UID、NodeID、在线、状态、故障位和最后接收时间。
- 依次执行 `ARMOR=ID?=1` 至 `ARMOR=ID?=4`，确认均返回 `OK`。
- 测试重复身份请求、非法 NodeID、枚举未完成、回复超时和 token/CRC 不匹配。

### 6.7 单节点故障和恢复

分别对每个节点执行：断电、拔 CANH、拔 CANL、断地、复位、软件进入异常状态、恢复供电。

记录：

- 最后一帧正常回复时间。
- L431 判定离线的时间。
- 是否触发一次且仅一次重枚举。
- 其他三个节点在故障期间的回复间隔。
- 故障节点恢复后的枚举耗时和 NodeID。
- `CAN_RX_DROP_COUNT`、发送错误、Bus-Off 和恢复计数。

### 6.8 L431 CAN 驱动和控制器异常

- 三个 TX 邮箱持续占用超过超时阈值。
- 发送帧无 ACK。
- 仲裁丢失。
- ACK、位、填充、格式、CRC 错误注入。
- CAN 控制器进入 Error Warning、Error Passive、Bus-Off。
- Bus-Off 后恢复期间继续请求发送。
- RX FIFO 突发超过软件队列处理能力。
- RX 队列满、ISR 高负载和主循环暂时延迟。
- 控制器停止、重新启动和状态异常。

通过标准：错误可从 `g_can_trace` 和 `bsp_can_diagnostics` 定位；发送邮箱最终释放；Bus-Off 能恢复；不会无限阻塞主循环；恢复后枚举和业务自动继续。

### 6.9 系统资源和实时性

在以下组合下测量主循环、ADC、看门狗和串口：

- 四板正常状态轮询。
- 四板同时发送命中/故障/状态帧。
- 枚举突发加枪管 CAN 通信。
- CAN 错误风暴。
- 串口日志大量输出。

记录 CPU 占用、主循环周期、ADC 丢帧、看门狗复位、RX 队列深度、TX 等待时间和 CAN 总线负载。CAN 总线负载建议长期低于 70%，短时枚举突发必须有明确上限；不能让单次发送等待超过设计超时。

### 6.10 电源、复位和长期运行

- L431 冷启动、热启动、软件复位、看门狗复位。
- 四板分别冷启动、热启动和随机延迟启动。
- L431 与装甲板不同步断电、上电。
- 低电压、瞬时掉电和电源恢复。
- 连续运行 1 小时、8 小时、24 小时。

长期测试每 10 分钟保存一次计数器快照，检查计数器增长是否与实际帧数一致，重点关注重复 `0x120`、Bus-Off、RX 丢帧、TX 失败和 NodeID 变化。

## 7. 专项验证：重复枚举问题

这是本项目的重点验收项。

### 7.1 正常运行基线

四板全部在线，抓包至少 10 分钟。自动统计：

```text
0x120 总数
每轮 0x121/0x122/0x123 数量
四个状态回复最大间隔
每轮枚举前最后一次状态回复时间
L431 的在线状态和 last_rx_tick
CAN 错误、Bus-Off、TX 失败和 RX 丢帧
```

通过标准：没有人为事件时 `0x120=0`；若出现 `0x120`，必须能由 L431 调试变量给出明确离线 NodeID 或 CAN 故障原因。

### 7.2 人为延迟和丢帧

只对一个节点制造 100 ms、300 ms、500 ms、900 ms、1100 ms 级别的回复缺口，观察：

- 何时置 `online=0`。
- 是否在阈值前恢复为在线。
- 是否错误触发重枚举。
- 重枚举期间其他节点是否仍被正常轮询。

### 7.3 枚举期间在线状态保护

在重枚举期间观察已有节点的状态帧：

- `last_rx_tick` 应持续刷新。
- 枚举未完成时不应依据旧时间戳置离线。
- 枚举完成后不应立即因旧时间戳再次启动枚举。
- 新枚举表只能在完整 UID 和 ACK 校验完成后原子替换。


分析脚本必须保留原始 CSV，不覆盖原始数据；输出报告、图表和解析异常列表。CSV 方向字段若不可信，报告中必须明确标注“只能依据 ID、时序和协议方向推断物理发送端”。

## 9. 测试执行顺序

1. 固件、芯片 UID、接线和终端电阻确认。
2. 单 L431 + 单装甲板基础通信。
3. L431 + 四板物理层和正常枚举。
4. 四板正常业务轮询和字段解析。

7. CAN 控制器错误、Bus-Off、邮箱和接收队列压力。

10. 1 小时、8 小时和 24 小时长期运行。
11. 复测所有失败项并形成回归清单。

## 11. 最终验收条件

以下条件全部满足，才判定 L431 与四个装甲板 CAN 通信通过：

- 四板连续冷启动和热启动各 10 次均能完成正确枚举。
- 正常运行 24 小时无非预期 `0x120`。
- 四个节点状态回复无异常长间隔，且无 RX 队列溢出。
- 单节点断开和恢复不导致其他节点永久失联。
- CAN 错误和 Bus-Off 可恢复，且不会造成发送永久停止。
- 命中事件不会重复扣血，ACK 重试符合协议。
- 状态、故障、LED 和身份查询字段全部通过。
- L431 无看门狗复位，ADC、电源保护和串口任务保持正常。
- 所有异常均能通过抓包、诊断变量或硬件波形定位。
